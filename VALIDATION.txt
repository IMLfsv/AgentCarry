NATIVE SYNTHETIC CASE: CORE ACCEPTANCE PASS.
Source: four visible messages in a synthetic Codex paginated rollout and a small
project with JSON input and a UTF-8 Chinese filename. A conversation-only marker
was absent from project files and the continuation prompt.

1. Initial startup failed because user_version=0 triggered legacy migration that
   discarded root metadata and project association. The writer now uses version 1.
2. Control runs with the installed backend in disposable child-only profiles
   reproduced the failure and verified the fix. No login state was copied; model
   endpoints used loopback. The harness stopped only its own backend processes
   after startup; those runs alone did not prove model replies or GUI operation.
3. The fixed candidate was installed with fresh backups and process guards.
   Existing conversations and project configs were preserved.
4. In the actual client the imported conversation continued successfully. It
   recalled the marker, read inputs/settings.json, and wrote result.txt = 343
   in the restored project. The original project and restored input hashes match.
5. Database inspection confirmed the same conversation/project IDs, the four
   original messages, new user turn, two file tool calls and final assistant reply:
   six visible messages and 11 stored steps. The recorded tools only read the
   expected JSON and wrote the result file, with no archive reads recorded.
6. The user confirmed the new reply remained visible after restarting the client.
   A new backend process/start time was observed. Post-restart checks confirmed
   all six messages, both tool calls, project binding, version 1 and result=343
   persisted; no duplicate conversation was created. The original calibration
   conversation retained its exact file hash.

EVIDENCE LIMITS:
UI visibility is user-reported; no screenshot-based UI test was performed.
Live verification used hash-stable DB/WAL copies with integrity checks, not a
transactionally guaranteed live SQLite snapshot. Fresh stopped backups were
used for installation. A consistent SQLite backup preceded the WAL checkpoint.

KNOWN FAILURE:
Original title preservation fails after continuation: title is empty and preview
uses the first message. Conversation identity, content and project are retained.

NOT PROVEN / NOT IMPLEMENTED:
Multiple real users' Codex native imports; long/complex native conversations; historical tool
or media migration; subagent parent reconstruction; global platform memory;
other App versions/platforms; file ACL or executable-mode preservation.
The new input pipeline is not fixture-restricted, but the native adapter remains
pinned to the observed Windows App build. The old trial installer stays isolated
as historical tooling. General input support is not proof of lossless native
conversion, support for all clients, or model-context retention for arbitrary
large histories. No multi-user or cross-OS native runtime claim is made.
